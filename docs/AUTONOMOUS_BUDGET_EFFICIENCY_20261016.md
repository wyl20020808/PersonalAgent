## 改动

- 规划建议使用剩余 Token 的 10%；执行建议留出剩余 Token 的 20% 给后续验收，其余按未验收任务数分配；验收可使用剩余额度。这些全部是建议，不是硬预留、强制任务切分或额外预算。任务完成数和用户调整后的累计账本决定下一轮建议。
- 提示明确要求合并独立读取和检查、只取相关输出、复用未变化的验证凭证；额外审查 Agent 或重复测试须有具体必要性。允许资源受限时提交可恢复的部分成果及未完成项，不能伪称验收通过。
- Codex 决策与执行 Worker 在本轮可信用量达到建议额度的 80% 时，通过官方 `turn/steer` 最多发送一次简短收尾提醒。绑定原 Thread 和 `expectedTurnId`，使用输入加输出，不重复计缓存，不使用范围不明的 last-request 数字。
- 请求为非阻塞；不支持、无响应、错误 Turn 回执均不触发重试、不启动新回合、不打断工具。已收到终态时不再提醒；终态与提醒交错时由 `expectedTurnId` 拒绝过期请求。请求及收到的结果记为 `resource-budget-notice`，不伪造用户授权。
- Claude/OpenCode 获得相同启动额度建议；运行中提醒本轮仅接入 Codex。未设置 Token 阈值时不生成分配或提醒。

Controller 原有调用边界阈值、未知计量暂停、停止、Session 恢复及验收职责均保留。提醒属于软引导，模型可能仍然超额；不存在提供商级硬封顶或已证明的节省比例。
