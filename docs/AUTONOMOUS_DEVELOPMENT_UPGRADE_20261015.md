# 全自动开发升级计划与第一阶段记录

日期：2026-10-15。执行方：外部 Codex。基线：本地 TEST `adc7ca23073778caeace47294152ddca221c6966`。任务分支：`feature/autonomous-task-agreement-20261015`。

## 用户确认的产品目标

用户先与决策者澄清大方向、成果范围及完成标准，再确认时间和 Token 投入。澄清优先使用具体问题、二至四个有说明的选项、推荐标记及可选自由补充。确认后自主规划、执行、验收、修订计划，直到目标完成、用户停止或没有合法可执行的路径。支持短任务及一天左右的长期任务；工作时长不是必须耗满的指标。开发 PersonalAgent 自身复用同一能力，不新增独立“自我迭代模式”。

用户可以中途增加或减少投入、修改方向。保留原 Run、已完成成果、用量历史与审计，只调整剩余工作。选择较高投入不扩大权限。

## 实施顺序

1. **需求入口与调整卡片（本次增量）**：全自动新会话先只读澄清，结构化选择问题，确认当前方案和投入，运行期间修改投入，通过已有引导交给决策者。
2. **自主决策与目标闭环（待实施）**：普通问题直接交决策者；正常决策不等待十分钟、不消耗异常接管次数；阶段完成时对照大目标，继续规划或依据证据结束。保留真实权限、用户停止和证据边界。
3. **长期运行与资源控制（待实施）**：持久化目标/授权/资源状态，区分预期范围和硬上限，用户修改上限时按累计用量而非重新计数处理；异常恢复核对、无进展调整、外部等待、独立任务推进、停止优先。精确 Token 数据缺失时不得声称硬上限得到保证。
4. **真实长期验收（待实施）**：多阶段真实目标连续工作，验证用户无需重复给方向；记录实际进展、用量、恢复及人工介入。真实一天验收不得用模拟时间、Mock 或进程存活代替。

## 第一阶段实现

- 开启实例全自动模式后创建的新开发会话先进入讨论，不直接创建开发 Run。已有历史会话保持兼容；全自动新会话的后续新任务重新澄清。
- 讨论结构化输出可包含最多三个问题，每题二至四个选项。验证推荐索引和问题 ID；有未回答问题时后端拒绝启动。
- 卡片支持点选、推荐说明、自由补充、独立的时间和 Token 三档。确认绑定最新方案消息 ID，过期方案不能启动；重复启动请求不创建重复 Run。
- 用户确认的投入写入会话、Run 初始目标及关联审计。运行中的修改带版本比较，通过原有 guidance 邮箱传递；桌面不改写运行中的 Controller state/audit。
- 修改投递与生效分开呈现。任务已停止或未运行时不擅自恢复；任务结束竞争下的投入修改不派生成新任务。
- 原有 Session、执行者、决策者配置及工作/空闲策略继续生效。

本阶段的档位是规划偏好，不是精确分钟数或强制 Token 上限。暂停期间修改投入、正式资源计量、后台自主接管升级属于后续阶段。界面选择可用不等于完整全自动开发升级完成。
