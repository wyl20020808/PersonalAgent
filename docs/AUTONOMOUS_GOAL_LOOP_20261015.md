# 全自动开发第二阶段：自主决策与目标闭环

日期：2026-10-15。执行方：外部 Codex。基线：TEST `4c68789fd2c9058b074eeee46fcb8e36ba9ef8f5`。任务分支：`feature/autonomous-goal-loop-20261015`。

## 本阶段行为

实例开启全自动模式后，新建 Run 将 `autonomousDevelopment` 固定写入配置。历史 Run 不被迁移，关闭全局开关影响新 Run 和异常接管；当前 Run 可由停止按钮停止。入口仍复用第一阶段的需求澄清、选择卡片与投入确认。

执行者以问题结束时，Controller 立即派给配置的决策者，不等十分钟。决策者可返回简短 `executorReply`，原任务、原执行 Session 继续；回复审计明确来自决策者，不伪造用户授权。需要改变剩余工作时仍可重新规划。决策者确认必须保留给用户的授权或必要事实时标记 userRequired，后台巡检不能代答。

最后一次任务验收同时核对整个目标，返回有理由的 `goalAssessment`。目标未完成时沿用 `followUpTasks` 追加任务，保留已验收 ID，任务间继续轮换执行 Session；目标完成则结束，不为了耗满时间或 Token 人为加任务。没有额外固定“再规划”调用。更新计划移除全部剩余工作时也必须记录目标已完成的依据。

Controller 只检查结构一致性、任务 ID/依赖与明确结论，不代替决策者判断测试、质量或目标实质是否完成。全自动模式拒绝缺失目标结论、结论与追加任务矛盾、重复 ID 或无效依赖，避免无效追加任务被丢弃后误报目标完成。普通模式保留原行为。

设置说明及时间线补充“决策者已答复”“大目标已验收/继续完成大目标”。权限、原调用限制、工作模式、唯一 Writer、停止和交付授权不扩大。
