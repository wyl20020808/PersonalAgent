# 全自动开发第三阶段：累计资源控制与防空转

日期：2026-10-16。执行方：外部 Codex。任务始于 2026-10-15，目录及分支保留该日期。基线：TEST `9e31aea087011c426f19c2476e39e1e572949bea`；分支：`feature/autonomous-resource-control-20261015`。

## 已实现

需求确认卡片增加独立于低/中/高规划偏好的运行限制：累计运行时间选择不限、30 分钟、2 小时、24 小时；Token 阈值选择不限、10 万、100 万、500 万。卡片显示已结算运行时间、已知 Token 下限及不完整调用数。默认不限，用户选择较高投入不扩大权限。

运行中或暂停后可以修改同一 Run 的投入。桌面只向原 guidance 邮箱投递结构化限制，Controller 在安全交接点读取并记录，消耗不重置、重复投递不重复应用。暂停时修改不会擅自恢复，用户点继续后生效。普通消息的数字不会被模型解释成实际预算授权。历史 Run 首次加入限制时复用原用量凭证和已记录的调用时长，不建立新 Run 来清零。

`resource-control.json` 保存限制、累计时间、已知 Token、计量完整性和无进展状态。写入由持有 Run 锁的 Controller 执行；桌面只读显示。正常暂停不累计运行时间。一次 plan/execute/review 调用内部的工具执行计入时间；到时发送中断信号，等待原适配器退出后保留现场。进程异常退出时，未结算时间保守计至恢复时刻，并明确记录不确定性，不将未知运行时间算作零。

用量取已有原生 `.usage.json` 回执：按 callId 去重；Codex 缓存输入是 input 的子集，不重复加；Claude/OpenCode 将单独报告的缓存输入合入总量。线程累计范围不明确、部分记录、失败或缺失用量均标记未知。设置 Token 阈值时，不完整计量会暂停。决策者和执行者获得精简的剩余资源摘要。

连续三次执行无可观察工作区变化且没有新增验收成果时，决策者重新规划剩余工作；随后再连续三次无进展则暂停，防止无期限重复调用。已验收任务或新用户引导会重置无进展计数，时间/Token 消耗不重置。它是停滞信号，不替决策者判断成果质量。

## 明确边界

- Token 是 Controller 调用边界阈值，不是提供商逐 Token 的硬封顶。一轮长调用、内部重试或双决策过程可能超出阈值，完成后不再派发下一轮。缓存输入计入数量，不转换为费用。
- 时间中断存在轮询和适配器退出耗时；正常统计主要覆盖模型与工具运行，未宣称覆盖所有 Controller 开销。崩溃后的保守时间包含不可判定的停机间隔。
- 无进展检测无法识别所有“改了文件但没有实质进展”的情况。重规划与任务验收仍由决策者负责。
- 没有运行一天持续实战，也没有覆盖所有 Claude/OpenCode 配额、断网、外部等待场景。当前用户实例未被替换，DEV/MAIN 未更新。
