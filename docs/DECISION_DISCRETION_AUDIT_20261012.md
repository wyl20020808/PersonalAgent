## 修改结果

用户授权目标后，由决策者决定任务数量、粒度、工作方法、方案内技术与架构取舍、必要验证，以及直接修复还是安排执行者处理。提示词说明当前调度方式，并把交接成本、风险、可恢复性作为参考方向，不要求固定任务数量或固定开发步骤。

- `real-agents.ts`：取消“小实现任务”、仅“小问题”可直接修复、任意需求不明确都转人工的引导。计划与验收共享当前自主开发模式说明；Context 目录按相关性按需读取，取消规划前全目录必读。显式 `minTasks` 提供给规划者，未配置则由其选择。
- `native-agent.ts`：按角色配置说明职责，不按模型名称限制能力；方案内架构选择交决策者。提交和整合依据已有用户授权与项目规则，避免通用禁止条款抵消已授权的 TEST 自主整合。
- `schema.ts` 与导出 Schema：取消计划最多 20 项、依赖最多 20 项及显式最低任务数最多 20 的固定上限。任务 ID、依赖有效性和完成记录继续校验。
- Codex 决策适配器：授权开发使用既有原生开发工具权限；显式只读讨论和初始协作周期仍只读。CC/OpenCode 同样接收初始协作周期的只读标记。工作/空闲策略和 Hook 不改变。
- OpenCode 决策适配器：在核实 Session 所有权后，按当前只读/开发模式切换该 Session 的权限；不重置 Session，不改变模型，不修改共享配置。
- 同步 AGENTS、CLAUDE、统一工作规则、两份执行契约、README、三分支治理与双实例运行说明；修正运行说明里 pass 后仍等待用户的旧描述。
