# 单个附件大小上限统一为 100 MB

- 现象：图片超过 2 MiB、文本超过 200 KB 会拒绝上传；另有 IPC 长度、Run schema、原生附件读取和 Claude 序列化本地限制。
- 用户要求：单个文件上限提高为 100 MB。
- 实现：统一常量为 `100 * 1024 * 1024` 字节（100 MiB，界面同时标注）。前端选择、IPC schema、后台字节校验、Run manifest 与原生读取一致；base64 长度按编码膨胀换算，不把编码后长度误当原文件大小。删除本地 Claude 9 MiB 序列化限制，不截断附件。
- 保持：每条消息最多 8 个附件，现有图片和 UTF-8 文本类型范围，归属/路径/哈希验证。项目文件浏览器的预览上限与上传无关，保持原样。
- 验证：构建和 typecheck；附件与原生多模态针对性测试；离屏聊天界面检查。尺寸边界使用 File 元数据与 schema 校验，不分配 100 MiB 压力样本。实际 3 MiB 图片格式缓冲区、3 MiB 文本通过解码，10 MiB 文本通过 Run 保存与 Claude 序列化；没有进行 100 MiB 远端模型请求。
- 边界：服务商仍可能限制请求大小、图片尺寸及上下文长度，上传成功不代表任意模型都接受 100 MiB 原始内容。
- 状态：独立修复工作区完成；与提醒点修复一并保留，尚未提交或合并 DEV。
