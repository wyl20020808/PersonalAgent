# 普通聊天不能恢复任务、补充消息需要手动派发

状态：已解决主要入口与调度问题，任务分支内待正式交付。

原 `SessionStore.sendLocked` 遇到非 completed Run 只将消息留为 pending；前端通过消息用途选择器要求用户区分补充、恢复和返工。`App.tsx` 还保留独立创建页面、导航及启动表单。

本次加入基于可信运行状态的消息路由，正常完成后顺序处理已排队消息，暂停后的新消息直接进入原 Run 的恢复或返工流程；保留重复请求校验、停止控制、附件校验和正式审批边界。前端只保留统一发送，新建入口集中在聊天页面。

详细行为和验证边界见 `docs/CHAT_INTAKE_2026-10-11.md`。当前不支持工具执行中途实时插入，也不在应用重启后自动重放待办；此类消息仍保留可见，并可明确重试。
