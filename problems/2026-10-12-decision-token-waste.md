## 事实与原因

DEV 原 Run `922a7176-8dea-4269-977a-ab785b4927d0` 的 t01 在通过后未推进，累计送审 8 次。每次提示约 159 KB，主要包含 Primary 既有修改的约 150 KB diff。恢复后的第 10 次调用继续使用同一 Opus Session，原生 CLI 日志确认缓存写入 823162、缓存读取 1683106、输出 8852 Token。大部分输入来自积累的历史，不能将缓存读取和写入直接换算为订阅扣额。

重复 pass 推进及旧 pass 复用已有 TEST 修复，本任务补充恢复一致性和增量证据：snapshot-free Run 保存 Git patch 分段哈希，不备份文件、不扫描全项目，只将当前变化的 patch 段交给决策者。缺少旧检查点时，不把全量旧 diff 注入为本轮变化；显式标记覆盖不足，保留完整证据文件供原生工具检查。

本任务由外部 Codex 开发，基线 TEST `2115234`，分支 `fix/decision-token-efficiency-20261012`。当前 DEV 运行版本保持不变。

## 修复与边界

- 源码 diff 摘录限制为本轮 16 KB、当前任务 8 KB；完整证据保存在 Run 内带内容哈希的独立 JSON。编译产物摘要不挤占源码摘录。
- 未变化的旧 Git patch 段不发送；已经变动的脏文件仍可能包含既有行，不能宣称精确行级差异。未跟踪文件、忽略文件、外部工作树、HEAD 变化仍须决策者通过原生工具核对。
- Claude 决策者调用使用官方 `--autocompact 100k` 和仅作用于子进程的窗口配置，由 Claude 在原 Session 内压缩，不创建新 Session、不改模型、不删除历史、不修改用户设置。执行者调用保持原设置。CLI 需支持该参数；本机已核对支持。显式关闭原生压缩的配置仍可能影响实际压缩行为。
- 已通过成果恢复时保持证据字段序列一致，避免新增增量字段导致旧 pass 校验失败而重新调用。
- 原有 snapshot-free 测试中 4 处断言仍期待用户逐项确认，在未修改的基线中也失败。本任务更新为区分决策者验收和用户批准；需要人工观察的用例由决策者明确返回 human，保留人工入口。
