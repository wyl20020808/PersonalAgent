# 测试产物含技能目录链接且泄漏到仓库根目录

- 状态：待处理
- 发现场景：开发“目标项目 test 分支硬性规则”（feature/project-test-branch-20261014）时运行完整回归并做收尾清理。
- 相关模块：`test/conversation-discussion.test.ts`、共享 Skills 注入（`src/shared-skills.ts`）的测试夹具、回归测试输出目录。

## 现象

1. 完整回归后，任务 Worktree 的 `.validation/` 中出现数千个目录联接（一次 5810 个、基线 Worktree 2377 个），指向本机真实 Skills 目录（例如 `native-skills/<hash>/skills/brainstorming`）。部分测试不使用 `PERSONAL_AGENT_TEST_ROOT`，仍写入仓库内的 `.validation/`。
2. `conversation-discussion.test.ts` 运行后在仓库根目录留下未跟踪的 `test-projects/discussion-*` 目录。
3. 这些路径常超过 Windows 路径长度限制，`git worktree remove` 报 “Filename too long”，只注销工作树、留下文件。

## 影响

- 用 `Remove-Item -Recurse` 等会跟随联接的命令清理测试产物，可能删除用户真实 Skills 内容；本次按清理规则先逐个删除链接（不带递归）再删目录，用户 Skills 条目数前后一致（6/6），未造成损失。
- 仓库根目录出现散落产物，违反清理规则的禁止事项，且回收 Worktree 需要额外手工处理。

## 证据

本次清理输出：`.validation (links first: 5810)`、`project-test-branch-baseline-20261014 (links first: 2377)`；`git status` 显示 `?? test-projects/`。

## 原因

已确认：共享 Skills 测试夹具在测试运行目录下创建指向真实 Skills 的联接，且部分测试的输出目录未遵循 `PERSONAL_AGENT_TEST_ROOT`。根因细节（具体哪些测试、联接是否必须）待核实。

## 建议下一步

让所有测试输出遵循 `PERSONAL_AGENT_TEST_ROOT` 并在结束时自行删除联接；`conversation-discussion` 测试改用临时目录；考虑测试中用复制或只读快照代替指向真实 Skills 的联接。
